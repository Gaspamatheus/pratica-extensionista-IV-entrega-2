1. Visão geral

A solução tem três partes, definidas na arquitetura da entrega 1: o app (PWA em React + Vite), a API REST (Spring Boot 3.5, Java 17) e o banco MySQL 8.4. Cada parte roda em um contêiner Docker, e o arquivo docker-compose.yml na raiz do repositório descreve e liga os três. Com o Docker instalado, um único comando sobe o sistema inteiro, igual em qualquer computador ou servidor.

O código é versionado no GitHub. A cada push, o GitHub Actions testa a API e o app, confere se os contêineres sobem e envia a análise de qualidade ao SonarCloud (CI). Quando a branch main recebe um merge aprovado, as imagens Docker são geradas e publicadas no GitHub Container Registry (CD).

2.1 Imagem da API (api/Dockerfile)

Build em dois estágios (multi-stage):

  1. Build: imagem maven:3.9.11-eclipse-temurin-17. Copia primeiro só o pom.xml e baixa as dependências; assim, quando apenas o código muda, o Docker reaproveita essa camada e o build fica rápido. Depois compila e gera o .jar (os testes rodam na CI, não aqui).
  2. Execução: imagem eclipse-temurin:17-jre, só com o Java de execução e o .jar: sem Maven e sem código-fonte, a imagem fica menor e com menos pontos de ataque. O processo roda com o usuário gado, não como root. O HEALTHCHECK consulta /actuator/health, que só responde UP quando a API conecta ao banco. A JVM usa até 75% da memória do contêiner.

2.2 Imagem do app (app/Dockerfile e app/nginx.conf)

  1. Build: node:22-alpine roda npm ci e npm run build, gerando a pasta dist/ com o app, o manifest e o service worker do PWA.
  2. Execução: nginx:1.28-alpine serve o dist/. A configuração:
    • repassa /api/ e o Swagger para o contêiner api (proxy reverso), então app e API ficam na mesma origem e o navegador não precisa de CORS;
    • envia à API o endereço e o protocolo originais (Host, X-Forwarded-Host, X-Forwarded-Proto), para a API reconhecer que a chamada vem do próprio app, inclusive atrás do túnel HTTPS;
    • manda as rotas do React Router (/animais, /vacinas/nova...) para o index.html;
    • marca sw.js, index.html e o manifest como no-cache, para o app perceber quando há versão nova, e guarda por 1 ano os arquivos de /assets, que têm hash no nome;
    • comprime com gzip os arquivos de texto.

2.3 Ordem de inicialização

O Compose usa health checks para subir na ordem certa: a api só inicia quando o MySQL responde ao mysqladmin ping, e o web só inicia quando a API está UP. Todos têm restart: unless-stopped: voltam sozinhos se caírem ou se o computador reiniciar com o Docker aberto.

3. Rede, portas e fluxo de uma requisição

Os contêineres ficam numa rede Docker própria (interna) e se encontram pelo nome do serviço: a API conecta em jdbc:mysql://db:3306/gado_corte e o Nginx em http://api:8080.

EndereçoO que abre
http://localhostApp (login gerente / gerente123 ou funcionario / func123)
http://localhost/swagger-ui.htmlDocumentação interativa da API (também em :8080)
http://localhost:8080/actuator/healthSaúde da API ({"status":"UP"})
localhost:3306MySQL, para o Workbench (usuário gado_app). Só aceita conexões do próprio computador.

Exemplo: um funcionário registra uma pesagem no app.

  1. O navegador envia POST /api/pesagens com o token JWT para http://localhost (contêiner web).
  2. O Nginx vê que o caminho começa com /api/ e repassa para http://api:8080/api/pesagens.
  3. A API valida o token (filtro JWT), aplica as regras (animal ativo, data válida, idCliente não repetido) e grava no MySQL pelo JPA/Hibernate.
  4. A resposta volta pelo mesmo caminho. Se não houver internet, o app guarda a pesagem no IndexedDB e repete os passos quando a conexão voltar.

4. Configuração e variáveis de ambiente

Nenhuma senha fica fixa no código. O Compose lê o arquivo .env da raiz (criado a partir de .env.example), que fica fora do Git. Sem .env, valem os padrões de desenvolvimento abaixo.

VariávelPadrãoUso

5. Como subir o ambiente

5.1 Pré-requisito

Docker Desktop (Windows ou macOS) ou Docker Engine com o plugin Compose (Linux). No Windows, o Docker Desktop usa o WSL 2; o instalador oferece ativá-lo. Não é preciso instalar Java, Node nem MySQL: tudo roda dentro dos contêineres.

5.2 Passo a passo

# 1. Na pasta do projeto
cd pratica-extensionista-IV-entrega-2

# 2. Criar o .env (opcional; sem ele valem os padrões)
copy .env.example .env          # Windows
cp .env.example .env            # Linux/macOS

# 3. Construir as imagens e subir tudo em segundo plano
docker compose up -d --build

# 4. Acompanhar até os três ficarem "healthy" (leva cerca de 1 minuto na primeira vez)
docker compose ps

Depois é só abrir http://localhost.

5.3 Comandos do dia a dia

ComandoO que faz

6. Banco de dados, persistência e backup

  • Os arquivos do MySQL ficam no volume Docker dados-mysql, que sobrevive a down, atualizações de imagem e reinícios.
  • O script api/database/gado_corte.sql é montado em /docker-entrypoint-initdb.d. O MySQL o executa só na primeira subida, com o volume vazio. Ele pode ser rodado de novo sem duplicar nada e também serve para criar o banco num MySQL instalado direto no Windows (MySQL Workbench).
  • O banco usa utf8mb4, então acentos e emojis são gravados corretamente.
# Backup
docker compose exec db sh -c "mysqldump -uroot -p\"$MYSQL_ROOT_PASSWORD\" gado_corte" > backup.sql

# Restaurar
docker compose exec -T db sh -c "mysql -uroot -p\"$MYSQL_ROOT_PASSWORD\" gado_corte" < backup.sql

7. PWA, HTTPS e acesso pelo celular

Os navegadores só instalam um PWA e ativam o service worker (uso offline) em HTTPS ou em localhost. No computador, http://localhost já funciona. Para o celular há duas opções:

7.1 Túnel HTTPS (recomendado para teste e apresentação)

docker compose --profile tunel up -d
docker compose logs tunel | findstr trycloudflare     # Windows
docker compose logs tunel | grep trycloudflare        # Linux/macOS

O log mostra um endereço como https://palavras-aleatorias.trycloudflare.com. Aberto no celular, ele chega ao Nginx pelo túnel da Cloudflare, já com certificado válido, e funciona em qualquer rede, inclusive 4G. No Android, toque em Instalar; no iPhone, Compartilhar > Adicionar à Tela de Início. O endereço muda a cada vez que o túnel sobe e não exige conta.

7.2 Publicação definitiva

Em um servidor (VPS) com domínio próprio, os mesmos contêineres sobem com docker compose pull && docker compose up -d, usando as imagens do GHCR. O HTTPS fica com um proxy na frente do web (Caddy, Traefik ou Nginx com Let's Encrypt) ou com um túnel nomeado da Cloudflare. Nesse caso, trocar JWT_SECRET e as senhas no .env e não publicar as portas 8080 e 3306.

8. Segurança

  • Segredos fora do código: senhas e a chave do JWT vêm do .env (ignorado pelo Git) ou dos secrets do GitHub.
  • Banco: a API usa o usuário gado_app, com acesso só ao banco gado_corte, e não o root. A porta 3306 é publicada só em 127.0.0.1: outro computador da rede não alcança o MySQL.
  • Senhas dos usuários guardadas como hash BCrypt; login devolve um token JWT assinado com validade limitada.
  • Perfis: GERENTE faz tudo; FUNCIONARIO consulta e lança pesagens e vacinas. A API confere o perfil em cada rota.
  • Mesma origem: o Nginx serve o app e a API pelo mesmo endereço, e a API recusa chamadas de navegador vindas de outros sites (CORS só para as origens configuradas).
  • Contêineres: a API roda com usuário sem privilégio; as imagens finais não têm compilador nem código-fonte.
  • CI: os workflows têm permissões mínimas (contents: read); só a CD recebe packages: write para publicar imagens.

9. Integração e entrega contínuas (CI/CD)

9.1 CI (.github/workflows/ci.yml)

Roda em todo push nas branches main, develop e feature/** e em todo pull request. Os jobs:

JobO que fazFalha quando
BackendJava 17 (Temurin) com cache do Maven; mvn -B verify roda os testes JUnit 5 + Mockito e de integração (MockMvc + H2) e gera a cobertura do JaCoCoalgum teste falha ou o código não compila
FrontendNode 22 com cache do npm; npm ci, npm run test:coverage (Vitest + Testing Library, inclusive a fila offline) e npm run buildteste falha ou o build do PWA quebra
Infravalida o docker-compose.yml, constrói as duas imagens, sobe MySQL + API + Nginx e faz login e listagem de animais pelo Nginx, como um usuário fariaum Dockerfile quebra, um contêiner não fica saudável ou a API não responde pelo app
SonarClouddepois de Backend e Frontend, envia código e cobertura (Java e JavaScript) ao SonarCloud o Quality Gate reprova, se for marcado como obrigatório

Um push novo na mesma branch cancela a execução anterior, para não gastar minutos com código que já mudou.

9.2 CD (.github/workflows/cd.yml)

É disparada quando a CI termina com sucesso na main (ou à mão, em Actions > CD > Run workflow). Constrói as imagens gado-corte-api e gado-corte-web do commit aprovado e publica no GitHub Container Registry com duas tags: latest e sha- mais o hash curto do commit, que permite voltar para uma versão anterior (TAG=sha-1a2b3c4 no .env). Usa cache de camadas do próprio GitHub Actions para builds mais rápidos e o GITHUB_TOKEN do workflow, sem precisar criar senha.

Em repositório privado, as imagens também nascem privadas. Para baixá-las em outra máquina, faça docker login ghcr.io com um token de acesso (permissão read:packages) ou torne o pacote público em GitHub > Packages > Package settings.

9.3 Configurar o SonarCloud (uma vez)

  1. Entrar em sonarcloud.io com a conta do GitHub e importar o repositório (Analyze new project), no modo de análise pelo GitHub Actions (desligar a Automatic Analysis).
  2. Conferir se a Project Key e a Organization mostradas batem com sonar-project.properties na raiz; se não, ajustar o arquivo.
  3. Gerar um token em My Account > Security e cadastrá-lo no GitHub em Settings > Secrets and variables > Actions com o nome SONAR_TOKEN.

Sem o secret, o job do SonarCloud apenas avisa e não falha: o restante da CI continua valendo.

10. Fluxo de branches

  • feature/nome-da-tarefa: cada funcionalidade ou correção. A CI roda a cada push.
  • develop: integração. Recebe as features por pull request, que só deve ser aceito com a CI verde.
  • main: versão estável. Recebe a develop por pull request; cada merge publica novas imagens (CD).

Recomenda-se proteger main e develop em Settings > Branches, exigindo os checks Backend, Frontend e Infra antes do merge.

12. Solução de problemas

SintomaCausa provável e solução
port is already allocated ao subirOutro programa usa a porta (MySQL do Windows na 3306, IIS/Skype na 80). Troque MYSQL_PORTA ou WEB_PORTA no .env (ex.: WEB_PORTA=8081).
api não fica healthydocker compose logs api. Access denied: as senhas do .env mudaram depois que o volume foi criado; rode docker compose down -v para recriar o banco.
Mudei o script SQL e nada aconteceuO script só roda com o volume vazio. Use docker compose down -v (apaga os dados) ou rode o script pelo Workbench.
O app mostra versão antigaO service worker guarda a versão anterior; aparece a faixa "Há uma versão nova do app": toque em Atualizar.
Celular não oferece instalarPrecisa de HTTPS: use o perfil tunel (seção 7.1).
Docker Desktop não inicia no WindowsAtive a virtualização na BIOS e o WSL 2 (wsl --install no PowerShell como administrador).
